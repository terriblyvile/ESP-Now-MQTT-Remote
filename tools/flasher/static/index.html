Remote Firmware Flasher

Flash a hub, read its ESP-NOW address off the boot log, then flash remotes that talk to it.

1 · Credentials

Written to include/secrets.h, which is gitignored. Only the hubs use these — a remote never joins WiFi.

2 · Radio and topics

The channel is the single most common reason a remote does nothing: ESP-NOW has no channel of its own, so this must match the channel your access point runs on. An Ethernet hub never associates and pins the radio here instead.

3 · Base stations

Flash a hub, then capture its address. Remotes unicast to one hub's MAC, so a press reaches exactly one of them — both hubs can run at once.

This board has no USB — wiring and download mode
  1. Wire a 3.3V USB-to-serial adapter: TX→RX0, RX→TX0, GND, 3V3.
  2. Tie GPIO 0 to GND, then power the board up. It is now in download mode.
  3. Press Flash over USB above and wait for it to finish.
  4. Remove the GPIO 0 jumper and power-cycle the board so it runs the firmware.
  5. Press Capture address, then power-cycle once more so it reprints its boot banner.

There is no auto-reset on this board, because GPIO 0 is also the PHY clock input. That is why steps 4 and 5 are manual, and why capture here listens rather than pulsing reset.

Over-the-air uploads use the hostname the hub advertises (esp_hub_wifi.local / esp_hub_eth.local) and the OTA password above. A hub has to be running working firmware already.

4 · Remotes
